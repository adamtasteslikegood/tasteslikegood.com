# uv Quick Reference for Backend Development

One-page cheat sheet for using `uv` with this project.

---

## What is uv?

**uv** is a fast Python package manager written in Rust. It's 10-100x faster than pip and automatically manages virtual environments.

- **GitHub**: https://github.com/astral-sh/uv
- **Docs**: https://docs.astral.sh/uv/

---

## Installation

```bash
# Recommended: Official installer
curl -LsSf https://astral.sh/uv/install.sh | sh

# Arch Linux
yay -S uv

# Via pipx
pipx install uv

# Verify
uv --version
```

## Essential Commands

### Project Setup

```bash
# Sync dependencies (creates .venv automatically)
uv sync

# Sync and update all packages
uv sync --upgrade
```

### Running Python Code

```bash
# Run any Python script
uv run python app.py
uv run python scripts/migrate_recipes_to_db.py

# Run Flask commands
uv run flask db init
uv run flask db migrate -m "Message"
uv run flask db upgrade

# Run Python one-liners
uv run python -c "print('Hello')"
```

### Managing Dependencies

```bash
# Add a package
uv add package-name

# Add a dev dependency
uv add --dev pytest

# Update a package
uv add --upgrade package-name

# Remove a package
uv remove package-name

# Show installed packages
uv pip list
```

### Virtual Environment

```bash
# uv manages .venv automatically - no activation needed!

# But if you want to activate manually:
source .venv/bin/activate
python app.py  # Works without 'uv run'
deactivate

# Or use uv shell (activates in new shell)
uv shell
```

## Project Files

### `pyproject.toml`
Defines dependencies and project metadata. Edit this to add new packages (or use `uv add`).

### `uv.lock`
Locked dependency versions for reproducibility. Auto-generated by uv. **Commit this to Git!**

### `.venv/`
Virtual environment directory. Auto-created by uv. **Do not commit!** (Already in `.gitignore`)

### `requirements.txt`
Not tracked in this repo. The Docker build exports one from `uv.lock` at image build time (`uv export --frozen` in the Dockerfile's export stage) — never commit one.

## Comparison: pip vs uv

| Task | pip/venv | uv |
|------|----------|-----|
| Setup venv | `python -m venv .venv` | Automatic |
| Activate | `source .venv/bin/activate` | Not needed |
| Install | `pip install -r requirements.txt` | `uv sync` |
| Run script | `python app.py` | `uv run python app.py` |
| Lock deps | `pip freeze > requirements.txt` | `uv.lock` (auto) |
| Speed | Minutes | Seconds |

## Advantages of uv

✅ **Fast**: 10-100x faster than pip  
✅ **Simple**: One command to sync everything  
✅ **Reproducible**: `uv.lock` ensures exact versions  
✅ **Safe**: Always uses virtual environments

## Troubleshooting

### "uv: command not found"

Install uv first:
```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Restart your terminal, or run:
```bash
source ~/.bashrc  # or ~/.zshrc
```

### "No pyproject.toml found"

Make sure you're in the Backend directory:
```bash
cd Backend
ls pyproject.toml  # Should exist
```

### Dependencies out of sync

```bash
# Resync from uv.lock
uv sync

# Or rebuild completely
rm -rf .venv
uv sync
```

### Want to use traditional activation?

```bash
uv sync                    # Create .venv
source .venv/bin/activate  # Traditional activation
python app.py              # Now works without 'uv run'
deactivate                 # When done
```

### Package not found

```bash
# Make sure uv.lock is up to date
uv sync

# Or add the package explicitly
uv add missing-package-name
```

## Flask Database Commands

```bash
# Initialize migrations (once)
export FLASK_APP=app.py
uv run flask db init

# Create migration after model changes
uv run flask db migrate -m "Description"

# Apply migrations
uv run flask db upgrade

# Rollback last migration
uv run flask db downgrade

# View migration history
uv run flask db history
```

## Migration from pip

Already have `requirements.txt`? Easy migration:

```bash
# Create pyproject.toml from requirements.txt
uv init
uv add $(cat requirements.txt | grep -v '^#' | cut -d'=' -f1)

# Or keep using requirements.txt
uv pip install -r requirements.txt
```

But this project already has `pyproject.toml` and `uv.lock`, so just run:
```bash
uv sync
```

## Best Practices

✅ **Always use `uv run`** for Python commands  
✅ **Commit `uv.lock`** to Git (like package-lock.json)  
✅ **Don't commit `.venv`** (already in .gitignore)  
✅ **Use `uv sync`** after pulling new code  
✅ **Use `uv add`** instead of editing pyproject.toml manually
