# Dependabot / security advisory triage — 2026-07-23

Related: [KAN-64](https://tasteslikegood.atlassian.net/browse/KAN-64) ("Document `.agent/skills` purpose and usage in Backend repo" — asks whether these dirs should be `.gitignore`d. Answer below: yes, and they should never have been tracked.)

noise generated by intentionally-vulnerable test fixtures belonging to the
`dependency-auditor` agent skill, which got committed by accident into the repo
five separate times.

not anything reachable from the running Flask app.

## Root cause

`.zed/`, `.github/skills/`, `.codex/skills/`, `.claude/skills/`, and `.agent/skills/`
each contain an **identical, byte-for-byte 565-file copy** of the same
`engineering-advanced-skills` bundle (agent-designer, dependency-auditor,
database-designer, etc. — the same skill pack described in the root CLAUDE.md's
gstack skill table). All five got committed to the Backend repo at some point
(`.zed`/`.agent`/`.claude` etc. landed in `e18b2f3` — Backend PR #29 — before the
IDE-ignore section of `.gitignore` existed), even though `.gitignore` already
lists `.zed/`, `.cursor/`, `.ai/`, `.agent/`, `.codex/`, `.claude/` under its
`# IDE` section. **`.gitignore` only prevents new untracked files from being
re-added — it does nothing for paths already committed**, so the ignore rule
for `.zed/` has been silently inert since it was added.

`dependency-auditor`'s own `SKILL.md` ships two deliberately-vulnerable fixtures
so the skill has something to detect when it audits a project:

- `test-project/package.json` — outdated/vulnerable npm pins
- `assets/sample_requirements.txt` — outdated/vulnerable pip pins (see excerpt below)

```
Django==4.2.29
psycopg2-binary==2.9.6
django-allauth==65.14.1
cryptography==46.0.7
requests==2.33.1
pyyaml==6.0
six==1.16.0
...
```

None of this is a dependency of the Flask backend or the Express/Angular
frontend — it's sample data for a skill that isn't even installed the same way
production code is (skills are `.gitignore`d at the parent-repo level
specifically so they *don't* ship — see root `CLAUDE.md`: "the `skills` and
`.gstack/` `.gitignore` entries keep agent skills out of git"). The Backend
submodule just never had the equivalent enforcement.

## What this PR does

- `git rm -r --cached .zed` — untracks the 565 files under `Backend/.zed/skills/`
  (working-tree copies are left alone; `.gitignore` already covers `.zed/` so
  they won't be re-added).
- Adds this findings doc.

This closes out the alerts filed against the five duplicated
`.zed/skills/dependency-auditor/*` manifests going forward (GitHub stops
scanning a manifest once it's no longer tracked).

## What this PR deliberately does NOT do

`.github/skills/`, `.codex/skills/`, `.claude/skills/`, and `.agent/skills/`
still carry the same 565 tracked files each (2,260 more files, accounting for
the remaining ~580 skill-fixture alerts). Untracking those wasn't part of the
request that opened this branch (scoped to `.zed` only) and touches more
surface area (`.github/` in particular also holds real CI workflow files
alongside the skills copy, so it deserves its own careful pass rather than a
blanket `git rm -r --cached`). Recommend a follow-up PR against KAN-64 that:

1. Confirms `.gitignore` covers all five (it already does).
2. `git rm -r --cached` each of `.github/skills/`, `.codex/skills/`,
   `.claude/skills/`, `.agent/skills/` (and the single stray file under
   `.cursor/skills/`).
3. Re-checks the Dependabot alert count afterward — expect it to drop from
   ~787 to ~62.

## Real alerts that still need normal triage (out of scope here)

- **31 alerts on `uv.lock`** — the actual Backend dependency lockfile. These
  are genuine and should go through the repo's normal Dependabot/CodeQL
  triage process (see prior triage note: `[[codeql-backlog-triage]]`-style
  pass), not this cleanup.
- **30 alerts on `requirements.txt`** — this file was deleted from tracking in
  Backend PR #215 (`61d9413`, "drop tracked requirements.txt"). It no longer
  exists on disk. These alerts are almost certainly stale and should clear on
  Dependabot's next dependency-graph resync; if they don't clear within a
  normal rescan cycle, they can be dismissed as "no longer used."
- **1 code-scanning alert** (`py/unused-global-variable`, `services/gcs_service.py`) —
  real but minor; unrelated to this cleanup.
- **0 secret-scanning alerts.**

## Follow-up (completed 2026-07-23)

The follow-up recommended above shipped as a second PR off this same commit
(after #229 merged): `git rm -r --cached` for `.github/skills/`,
`.codex/skills/`, `.claude/skills/`, `.agent/skills/`, and the stray file
under `.cursor/skills/` — 2,261 files. `.codex/`, `.claude/`, `.agent/`, and
`.cursor/` were already fully `.gitignore`d as whole directories (they hold
no other content), so no gitignore edit was needed for those three; `.github/`
holds real CI/workflow/dependabot/copilot content that must stay tracked, so
that PR added a scoped `.github/skills/` entry to `.gitignore` rather than
ignoring `.github/` wholesale. Verified before untracking that
`.claude/agents/prompt-optimizer.md` and `.agent/workflows/*.md` (real,
intentional files, not skill-bundle noise) were left untouched. All six
skill-bundle paths now show 0 tracked files; the remaining ~62 alerts
(`uv.lock` + stale `requirements.txt`) are unaffected and still need the
normal triage process described above.
